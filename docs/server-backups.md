# Server backups

After you unlock Termnest, saved SSH servers automatically start copying Claude and Codex conversations when connected. The first copy needs a connected server. New copies run every five minutes while the computer running Termnest is running and its vault is unlocked. Reconnecting catches up after an outage. Due servers with the oldest attempts go first, so a slow copy cannot keep the other servers waiting indefinitely. A failed or empty attempt does not replace a saved copy or its last successful time.

The backup card shows **Máy lưu**: the actual hostname and folder of the computer running Termnest. If Termnest runs on another computer, the copies are on that computer. They are not automatically on the laptop displaying the page.

Choose working folders to protect working files. Nothing outside those selected folders is implicitly included. Files include untracked work, project dotfiles (including project `.claude` folders), `.env`, and Git history. Folders named `bin`, `obj`, `target`, `venv`, and `.venv` are included because their names alone cannot identify disposable files. The configured cache/generated exclusions are folders named `node_modules`, `__pycache__`, `.next`, `.cache`, and `.termnest-trash`. Links, special files, and names unsafe for portable extraction are not copied; they make coverage partial. Root folders, the whole account home, account credential folders, and system folders cannot be selected.

Conversation copies include all `.jsonl` files under every account-home `.claude*/projects`, `.codex*/sessions`, and `.codex*/archived_sessions` folder, including older conversations. This automatic scope does not read CLI login, token, or key files. Source collection currently supports Linux SSH servers with Node.js available. Missing Node.js, unsupported systems, unreadable files, changing files, and exceeded limits produce an explicit failure or partial copy. Changing files are deferred to the next attempt; a copy is consistent per file, not a transaction across a running VM.

Use **View chat** to read a saved conversation, or browse saved files and download their full originals. Text previews are limited to 1 MiB; long conversations show the last portion. Original downloads preserve binary and large files. **Export** downloads the selected whole copy as a portable UTF-8/PAX `.tar` archive. Saved viewing, downloads, and exports work with the source disconnected or removed, without contacting it. Export is recovery to a folder you own; Termnest does not restore, overwrite, or delete anything on the server.

Removing a saved server retains its copies in the backup list. Those rows can stay in the list while you configure another server. A server shown only for its stored copies stays unconfigured; changing another server's settings does not restart backups for it. Removing a backup scope from the complete configuration list also retains its existing copies.

Termnest keeps 32 versions per server by default. Deleting a source file does not delete it from older retained copies. An incomplete attempt keeps the most recent complete copy even when the version limit is reached. Turning automatic backups OFF retains existing copies and cancels unfinished work before publication. **Run now** is an explicit one-time copy and works while the automatic schedule is OFF. Its failure or partial result remains visible with automatic backups still OFF; a retry shows progress without the previous error, and a complete manual copy returns to paused. Only one backup runs at a time; duplicate requests report busy. Closing Termnest cancels unfinished jobs safely.

Copies are encrypted in Termnest's DATA folder under `server-backups`. The stable content key is stored only inside the encrypted vault. Termnest saves that key and verifies a fresh encrypted vault backup before writing the first snapshot. Vault password changes preserve it. Keep the vault and its encrypted backup together with the encrypted server-backup folder when moving computers. Losing every vault copy containing that key makes the server copies unreadable. An unavailable or damaged key/store is reported; Termnest does not reset an existing store automatically.

Defaults limit each file to 256 MiB, each attempt to 1 GiB and 20,000 files, scanning to 100,000 entries and 64 directory levels, and encrypted storage to 10 GiB and 100,000 objects. A job has a ten-minute deadline. Preview, transfer chunks, listings, and exports use bounded buffers; exports do not stage plaintext files on disk. Limits stop or mark an attempt partial, never report full protection. Retention normally reclaims expired objects after a successful copy; files in active downloads/exports remain pinned until those readers finish.

These are future local conversation and working-file copies. They are not VM disk snapshots and cannot recover Ubuntu02 data from before a successful first backup. A disconnected VM or a sleeping, stopped, or locked Termnest computer cannot create new copies.

For development checks, controller fixtures represent a Linux VM's transport protocol using isolated synthetic files, so scheduling, settings, cancellation, encrypted storage, and offline recovery run on the native backend OS. Tests that execute the actual Linux source scanner are marked Linux-only; native macOS and Windows instead check that this scanner rejects unsupported source platforms. Protocol validation and the HTTP/authentication boundary remain active on all platforms. Fixture waits and child processes have deadlines so an early failure cannot leave a cancellation test waiting indefinitely. Passing on Linux does not establish native macOS or Windows acceptance; those checks must run on the respective machines.
