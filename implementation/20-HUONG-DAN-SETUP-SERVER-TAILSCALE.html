Setup Termnest trên Ubuntu server và dùng từ điện thoại

Tài liệu nội bộ. Cài một Termnest trên máy chủ luôn bật, mở từ điện thoại và laptop qua Tailscale. Tắt laptop, phiên vẫn chạy.

◎Mô hình

Hiểu trước khi làm.

Thành phầnVai trò
Ubuntu server (luôn bật)Chạy Termnest như dịch vụ termnest, giữ các phiên tmux, chạy Claude Code/Codex ở đây
TailscaleVPN riêng nối server, điện thoại, laptop. Không mở cổng ra Internet
Điện thoại / laptopMở giao diện web của Termnest qua địa chỉ https://<tên-máy>.<tên-mạng>.ts.net
Termnest chỉ lắng nghe 127.0.0.1 trên server (không bao giờ mở thẳng ra mạng). tailscale serve chuyển tiếp từ mạng Tailscale vào cổng đó.
Server tắt hoặc mất mạng thì điện thoại không vào được và các phiên tmux trên server dừng. Máy làm server phải luôn bật.

1Chuẩn bị server

Cần quyền root (hoặc sudo), Ubuntu 22.04 trở lên (64-bit Intel/AMD) và tmux. Không cần Node.js, không cần mã nguồn: file cài đã kèm sẵn mọi thứ.

  1. Cài tmux: 
    apt update
apt install -y tmux curl
  2. Chép file cài lên server (từ máy bạn): 
    scp Termnest-amd64.deb root@<địa-chỉ-server>:/root/
    Để file ở /root/ hoặc /tmp/. Để trong thư mục con riêng của root thì apt in ghi chú Download is performed unsandboxed as root. Đó chỉ là cảnh báo, cài vẫn thành công.

2Cài Termnest trên server

Kết quả: dịch vụ termnest chạy ở 127.0.0.1:7681 và tự bật lại khi server khởi động.

  1. Cài file .deb (apt tự kéo thư viện cần thêm; trên server không màn hình các thư viện giao diện vẫn được cài, bình thường): 
    apt install -y /root/Termnest-amd64.deb
  2. Tạo thư mục dữ liệu: 
    mkdir -p /var/lib/termnest
chmod 700 /var/lib/termnest
  3. Tạo dịch vụ chạy nền (không cần màn hình): 
    cat > /etc/systemd/system/termnest.service <<'EOF'
[Unit]
Description=Termnest
After=network-online.target
Wants=network-online.target

[Service]
Environment=TW_PORT=7681
Environment=TW_DATA=/var/lib/termnest
Environment=TW_PACKAGED=1
ExecStart=/usr/lib/Termnest/app/node-x64 /usr/lib/Termnest/app/server.js
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now termnest
  4. Kiểm tra: 
    systemctl status termnest --no-pager | head -5
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7681/
    Phải thấy active (running) và mã 200.
Termnest dùng Node.js đi kèm trong file cài (node-x64), nên server không cần cài Node riêng.
Chưa vào được từ điện thoại ngay. Máy chủ chạy rồi nhưng Termnest còn chặn tên miền Tailscale. Làm tiếp mục 3 và 4 (đặc biệt bước đặt TW_ALLOWED_HOSTS) mới mở được trang.

Đặt mật khẩu lần đầu

Thư mục dữ liệu mới chưa có mật khẩu. Đặt qua trang web bằng mã thiết lập dùng một lần (làm sau khi xong mục 3 và 4 để mở được trang, hoặc tạm dùng SSH tunnel):

  1. Tạo mã và gắn vào dịch vụ: 
    TOKEN=$(openssl rand -hex 24); echo "$TOKEN"
mkdir -p /etc/systemd/system/termnest.service.d
cat > /etc/systemd/system/termnest.service.d/setup.conf <<EOF
[Service]
Environment=TW_SETUP_TOKEN=$TOKEN
EOF
systemctl daemon-reload && systemctl restart termnest
  2. Mở https://<tên-máy>.<tên-mạng>.ts.net/#setup=<MÃ-VỪA-IN-RA> bằng trình duyệt, nhập mật khẩu mới (ít nhất 10 ký tự) hai lần.
  3. Xóa mã thiết lập ngay sau khi đặt xong: 
    rm /etc/systemd/system/termnest.service.d/setup.conf
systemctl daemon-reload && systemctl restart termnest
Quên mật khẩu không lấy lại được. Cách duy nhất là xóa /var/lib/termnest/vault.json, đặt lại mật khẩu bằng cách trên và thêm lại các máy chủ SSH.

Giữ mật khẩu và máy chủ đã thêm từ lần trước

Nếu có bản sao lưu thư mục data/ của một lần chạy trước, chép vào thay cho bước đặt mật khẩu ở trên. Dừng dịch vụ trước khi chép:

systemctl stop termnest
cp -a <thư-mục-sao-lưu>/. /var/lib/termnest/
chmod 700 /var/lib/termnest
systemctl start termnest

Nếu dịch vụ đã khởi động với thư mục trống thì vẫn chép được theo cách này, miễn là chưa đặt mật khẩu mới.

3Cài Tailscale

Kết quả: server, điện thoại, laptop cùng một mạng riêng.

  1. Tạo tài khoản miễn phí tại tailscale.com.
  2. Trên server: 
    curl -fsSL https://tailscale.com/install.sh | sh
tailscale up
    Lệnh in ra một link login.tailscale.com/a/…. Mở link, đăng nhập, cho phép máy.
  3. Trên điện thoại: cài app Tailscale (App Store / Google Play), đăng nhập cùng tài khoản, bật công tắc kết nối, chấp nhận yêu cầu tạo VPN.
  4. Kiểm tra trên server: 
    tailscale status
    Phải thấy cả server và điện thoại. Trong app trên điện thoại cũng thấy server với chấm xanh.
Cần bật MagicDNS và HTTPS trong trang quản trị Tailscale (login.tailscale.com/admin/dns) nếu tailscale serve báo chưa hỗ trợ.

4Đưa Termnest vào mạng Tailscale

Kết quả: có địa chỉ https riêng chỉ thiết bị trong mạng của bạn mở được.

  1. Chuyển tiếp cổng 7681: 
    tailscale serve --bg 7681
tailscale serve status
    Kết quả có dạng https://<tên-máy>.<tên-mạng>.ts.net (tailnet only). Chép địa chỉ này.
  2. Lấy tên đầy đủ nếu cần (bỏ dấu chấm cuối): 
    tailscale status --json | grep -m1 '"DNSName"'
  3. Cho phép tên đó trong Termnest (bắt buộc, nếu không sẽ báo “Bạn không có quyền xem trang này”, mã 403). Ghi thẳng bằng lệnh, đừng dùng trình soạn thảo của systemctl edit: 
    mkdir -p /etc/systemd/system/termnest.service.d
cat > /etc/systemd/system/termnest.service.d/override.conf <<'EOF'
[Service]
Environment=TW_ALLOWED_HOSTS=<tên-máy>.<tên-mạng>.ts.net
EOF
systemctl daemon-reload
systemctl restart termnest
    Chỉ có tên máy, không có https://. Nhiều tên thì ngăn cách bằng dấu phẩy.
  4. Kiểm tra (phải ra 200): 
    curl -s -o /dev/null -w "%{http_code}\n" -H "Host: <tên-máy>.<tên-mạng>.ts.net" http://127.0.0.1:7681/
File override.conf nằm riêng nên cài đè bản mới cũng không bị xóa. Nhưng nó gắn với tên dịch vụ: nếu bạn xóa dịch vụ termnest rồi tạo lại, hoặc đổi tên dịch vụ, phải tạo lại file này, nếu không điện thoại lại báo bị từ chối (403).

5Mở trên điện thoại

  1. Bật Tailscale trên điện thoại (công tắc “Connected”).
  2. Mở Chrome/Safari, vào https://<tên-máy>.<tên-mạng>.ts.net.
  3. Màn đăng nhập phải ghi “Mật khẩu Termnest” và có logo. Đăng nhập.
  4. Muốn dùng như app: menu trình duyệt → Thêm vào màn hình chính.
Giao diện điện thoại có thanh điều hướng dưới: Tổng quan và Terminal. Thẻ phiên, Yes/No và trả lời nhanh dùng như trên máy tính.

6Bảo mật

  • Không dùng tailscale funnel và không mở cổng 7681 ra Internet. Chỉ serve (tailnet only).
  • Chỉ mời đúng người cần vào mạng Tailscale. Ai vào được mạng là chạm tới màn đăng nhập Termnest, nên mật khẩu phải mạnh.
  • Trên server dịch vụ chạy bằng root. Người đăng nhập Termnest điều khiển được terminal của root. Cân nhắc chạy dưới user riêng cho an toàn hơn.
  • Không chia sẻ tên mạng Tailscale, địa chỉ 100.x.x.x hay ảnh chụp màn hình có đường dẫn nội bộ ra ngoài.

7Sự cố thường gặp

Điện thoại báo “Bạn không có quyền xem trang này” hoặc “Quyền truy cập bị từ chối” (403)

Chưa đặt hoặc đặt sai TW_ALLOWED_HOSTS. Kiểm tra systemctl show termnest -p Environment: phải thấy biến này, đúng tên .ts.net, không có https://. Lỗi thường gặp: gõ dưới dòng ### Lines below… trong trình soạn thảo nên bị bỏ qua, hoặc vừa tạo lại dịch vụ mà quên tạo lại override.conf.

Không mở được trang, hết thời gian chờ

Tailscale trên điện thoại chưa bật, hoặc server chưa online. Chạy tailscale status trên server, xem app trên điện thoại có chấm xanh cho server không. Kiểm tra tailscale serve status có dòng proxy tới 127.0.0.1:7681.

Đăng nhập được nhưng terminal không kết nối

Nghi lỗi WebSocket qua tên .ts.net. Chính sách bảo mật của Termnest chỉ ghi rõ cho ws://127.0.0.1. Chrome thường chấp nhận cùng tên miền, Safari có thể không. Cần sửa nhỏ trong code, báo người phát triển kèm trình duyệt đang dùng.

Hiện đặt mật khẩu mới thay vì đăng nhập

Thư mục /var/lib/termnest đang trống (hoặc TW_DATA trỏ sai). Nếu bạn muốn giữ dữ liệu cũ, đừng đặt mật khẩu vội, chép data/ cũ vào rồi khởi động lại dịch vụ.

tailscale serve báo lỗi cú pháp

Cú pháp lệnh thay đổi giữa các phiên bản Tailscale. Xem tailscale serve --help.

Xem log dịch vụ
journalctl -u termnest -n 50 --no-pager

9Cập nhật bản mới sau này

  1. Sao lưu dữ liệu: 
    cp -a /var/lib/termnest /var/lib/termnest.bak-$(date +%Y%m%d)
  2. Chép Termnest-amd64.deb bản mới lên server rồi cài đè: 
    apt install -y /root/Termnest-amd64.deb
systemctl restart termnest

Dữ liệu trong /var/lib/termnest và biến TW_ALLOWED_HOSTS được giữ nguyên.

10Thử bản vá trước khi phát hành (cho người phát triển)

Chép tạm các file giao diện đã sửa lên server để thử ngay trên điện thoại, không cần dựng file cài mới.

  1. Từ thư mục dự án trên máy phát triển: 
    scp public/app.js public/app.css public/index.html public/touch-scroll.js root@<địa-chỉ-server>:/usr/lib/Termnest/app/public/
ssh root@<địa-chỉ-server> systemctl restart termnest
  2. Trên điện thoại đóng hẳn tab rồi mở lại để tải bản mới.
Cách này chỉ để thử. Cài file .deb mới sau đó sẽ ghi đè lại các file này. Muốn bản sửa có mặt lâu dài thì phải phát hành bản mới và cài lại bằng .deb (mục 9).

11Dùng VPN công ty và SSH tunnel (Termius hoặc Termux)

Cho điện thoại đã có VPN công ty. Không cần Tailscale, không mở thêm cổng nào trên server: điện thoại bật VPN, rồi dùng SSH tạo “đường hầm” tới Termnest.

Cách này chỉ cần dịch vụ termnest đang chạy (mục 2). Không cần tailscale serve và không cần TW_ALLOWED_HOSTS, vì trình duyệt sẽ mở http://127.0.0.1:7681 trên chính điện thoại.

Chuẩn bị chung

  1. Bật VPN công ty trên điện thoại.
  2. Xác định địa chỉ SSH của server (ví dụ 10.10.62.170) và tài khoản (ví dụ root). Điện thoại phải tới được địa chỉ đó khi bật VPN.

A. Termius (iOS / Android)

  1. Mở Termius, thêm máy: Hosts → +, nhập Address là địa chỉ server, Username, mật khẩu hoặc khóa SSH, lưu lại.
  2. Kiểm tra bằng cách mở máy vừa thêm: phải vào được dòng lệnh của server.
  3. Vào tab Port Forwarding, bấm + → New Rule, chọn loại Local.
  4. Điền:
    ÔGiá trị
    Local port number7681
    Bind address127.0.0.1
    Destination address127.0.0.1
    Destination port number7681
    Hostchọn máy server vừa thêm
  5. Lưu rồi bấm vào quy tắc để bật (trạng thái Connected).
  6. Mở Chrome/Safari, vào http://127.0.0.1:7681. Thấy màn đăng nhập Termnest là xong.
Tôi chưa kiểm tra bản Termius miễn phí có cho dùng Port Forwarding hay không (có thể thuộc gói trả phí). Nếu bị khóa, dùng Termux hoặc ConnectBot (mục B, C).

B. Termux (Android)

  1. Cài OpenSSH (một lần): 
    pkg install openssh
  2. Mở đường hầm (thay địa chỉ và tài khoản của bạn), giữ phiên Termux này chạy: 
    ssh -N -L 7681:127.0.0.1:7681 root@10.10.62.170
    Nhập mật khẩu SSH. Lệnh đứng yên là bình thường, nghĩa là đường hầm đang mở.
  3. Mở trình duyệt, vào http://127.0.0.1:7681.
Android có thể tắt Termux khi chạy nền. Nên vào cài đặt pin của máy, cho Termux chạy nền không giới hạn, hoặc dùng termux-wake-lock.

C. ConnectBot (Android) hoặc app SSH khác có Port Forwarding

Thêm máy, vào phần Port forwards, tạo quy tắc Local: nguồn 7681, đích 127.0.0.1:7681. Bật rồi mở http://127.0.0.1:7681.

Bị lỗi?

Không mở được 127.0.0.1:7681

Đường hầm chưa bật hoặc đã rớt (app bị hệ điều hành tắt nền). Bật lại quy tắc. Kiểm tra VPN còn kết nối và điện thoại vẫn SSH được vào server.

SSH không kết nối được tới server

VPN chưa bật, hoặc VPN công ty không cho điện thoại tới server đó. Hỏi bộ phận IT. Thử từ điện thoại: mở dòng lệnh SSH thường tới server trước khi tạo đường hầm.

Đăng nhập được nhưng trang trắng hoặc báo từ chối

Cổng cục bộ 7681 trên điện thoại đang bị quy tắc khác chiếm. Tắt các quy tắc cũ rồi bật lại, hoặc đổi Local port sang 7682 và mở http://127.0.0.1:7682.

Bảo mật: server không phải mở cổng ra ngoài. Phải qua VPN, rồi đăng nhập SSH, rồi mới tới màn mật khẩu Termnest.
